T10 - RADIUS outage fallback (authentication event server dead)

Date: 2026-10-28
Platform: IOSvL2 15.2(20200924:215240)
Device: SW2, interface GigabitEthernet0/3 (STAFF-PC3)

Setup
-----
SW2 Gi0/3:
  authentication event fail action authorize vlan 30
  authentication event server dead action authorize vlan 30
  authentication event no-response action authorize vlan 30
  authentication order dot1x
  authentication port-control auto
  dot1x pae authenticator
Global:
  radius-server dead-criteria time 10 tries 2

The RADIUS container was stopped (docker stop radius), the 802.1X session was
cleared and the supplicant re-ran EAPOL. IOS marked the server dead and applied
the configured server-dead VLAN on the first fresh authentication attempt.

Result: PASS - the port moved to VLAN 30 and the client obtained a DHCP
lease in 192.168.30.0/24. As with the wrong-password fallback, the guest ACL
still blocks staff, RADIUS and MQTT.

Notes
-----
* IOS marks the server dead for the failed transaction and immediately probes
  it again, so %RADIUS-4-RADIUS_DEAD (and the matching _ALIVE) repeat while
  the server is down. The port stays in VLAN 30 for the whole outage.
* The port moves in about 10-20 seconds with timeout 5 / retransmit 3 and
  dead-criteria time 10 tries 2.
* A re-authentication timeout alone does not move an already authorized port;
  the test needs a fresh session (clear the session / bounce the link).
